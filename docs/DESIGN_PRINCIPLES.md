# Chore Safari デザインプリンシプル

**目的:**
機能肥大化による「飽き」と「迷い」を防ぎ、Chore Safari の本来の目的である**「現実のお手伝いの習慣化」**と**「知識の向上」**にフォーカスし直すための設計原則。今後の機能追加・削除・UI変更は、すべてこの原則に照らし合わせて判断する。

## 1. 現実(リアル)が主役、デジタルは「ごほうび」

ゲーム内の行動よりも、現実世界の行動(お手伝い・生活習慣)を圧倒的に高く評価する。

- **Do:** コインの主な獲得源を「現実のお手伝い」に限定する。お手伝いをした時の演出は最も豪華にする。
- **Don't:** アプリ内のミニゲームや施設管理だけで、延々とコインが稼げる自己完結ループを作らない。

## 2. 「ハマりすぎない」健康的な距離感

子供がデジタル世界に没入しすぎず、適切なタイミングで現実世界に戻れる仕組み(ストッパー)を組み込む。

- **Do:** 1日のプレイに明確な「終わり(上限)」を設ける(例:アクティブ狩りは1日〇回まで、夜間は「動物たちも寝ているよ」として機能を制限する)。
- **Don't:** 無限に遊べてしまう「周回(グラインド)要素」や「終わりのないタスク」を作らない。

## 3. 迷わない、一直線の「コアループ」

選択肢が多すぎると子供は認知負荷で離脱する。「次に何をすべきか」が1秒で直感的にわかるようにする。

- **Do:** 【 お手伝い → コイン獲得 → 罠を仕掛ける → 図鑑が埋まる 】という最短ルートにUIを集中させる。複雑な施設(農場・物流・動物園など)は初期状態では隠すか、思い切って削る(プログレッシブ・ディスクロージャー)。
- **Don't:** 画面上に常にたくさんの通知バッジや未解放のピンを表示して急かさない。

## 4. 学びを「作業」ではなく「冒険の鍵」にする

知識の向上(クイズやAI対話)を、単なるお勉強モードではなく、ゲームを進めるために必要な「意味のあるステップ」として統合する。

- **Do:** 「この動物を捕まえるには、生態についてのクイズに正解して特別な罠を作る必要がある」など、知的好奇心とゲームの進行を直結させる。
- **Don't:** ゲームの文脈と無関係な、単なる「テスト」としてクイズを唐突に出題しない。

## 5. 摩擦を減らし、達成感を即座に

子供は「面倒くさい」と感じた瞬間にやめてしまう。複雑なシステムは極力簡略化し、アクションに対するフィードバックは即座に行う。

- **Do:** アイテムのクラフトやガチャ(クレーンゲーム)の工程を見直し、タップ数を最小限にする。
- **Don't:** 目的の画面にたどり着くまでに、何度も階層を潜らせたり、無駄な確認モーダルを挟んだりしない。
